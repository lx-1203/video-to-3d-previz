# 可复制的任务与验收记录

按任务规模选用下列表格，不要求每次新建一整套空文件。未有证据的状态保持“未验证”，不要预填通过。

## 任务合同

- 项目/片段ID、用户目标、完整覆盖范围：
- 原片路径与SHA-256、尺寸、fps分数、解码帧数、视频/音频起止：
- 基线工程与SHA、已认可画风/配色、实际Blender与编码器版本：
- 模型/片段ID→工程/角色对象/镜头/帧段映射；认可参考对象、启用/禁用状态、眼条方式、头身连接/是否允许外露颈部、手型及肩肘腕掌端比例：
- 环境配色模式（灰模/语义色/原片还色）、主要表面色块和明暗、参考来源、生效材质/渲染颜色来源与覆盖设置、同机位试渲：
- 标记选色：角色ID/标记类型、承载材质与实际底色、色彩空间、互补色算法、最终标记色、亮度对比/回退理由、跨镜复用方式；采用来源色板时第四角色全镜黄色：
- 输出：工程；白模尺寸；对照总尺寸/每格尺寸/上下顺序；fps；编码/像素格式；实测码率门槛：
- 原声：流复制归档；时间轴格式；最终是否需要转码；内容、起点、尾部要求：
- 输入不足/推断/当前不能验证的事项：
- 本轮授权改动对象与帧段、保持项、负责整合者：
- 视觉门槛、相似度定义、标注误差预算、预设抽样和必须连续检查的区间：

## 交付来源链

记录每个文件实际路径、字节数、SHA-256和依赖，不只记录目录名：

- source_video → source_audio / timeline_wav
- baseline_blend + build_scripts / external_assets → frozen_blend
- frozen_blend + render_settings → frame_manifest（逐帧编号/尺寸/SHA）
- frames + source_video + shared_encoded_audio + encode_settings → white_mp4 / comparison_mp4
- native_audit + visual_review + media_verification + batch_binding → selected_delivery

后继工程复用旧渲染时，额外给出 nonvisual_change_bridge、旧渲染源SHA和验证范围；保留原manifest，不重写历史。

## 验收矩阵

| requirement_id | 需求 | 原生证据 | 视觉证据 | 成片证据 | 当前输入SHA | 结论与限制 |
|---|---|---|---|---|---|---|

逐项使用 passed / failed / unverified / not_applicable，不把没有结果视为 passed。报告必须同时记录：
- 实际执行命令/工具及退出结果；
- 查看过的帧段、图像尺寸、完整解码/正常速度播放/试听的实际范围；
- 原声延迟的单位与实测值、头尾完整性、两种输出AAC是否一致；
- 局部与整体评分，原片N/A和候选缺失分别处理；
- 眼部/胸前焦点标记自动选色记录、底色变更后的重新计算、全镜颜色稳定性与实际画面可辨性；
- 环境还色、逐镜背景/门洞/俯仰/遮挡、人物尺度与间距的实际画面对照；
- 球面眼条侧面与转头、头身连接/颈部、腕掌/掌端、道具可见性及接近—接触—分离的检查范围；
- 行走、转身、离画、挥手、张臂、贴面互动的连续帧/正常速度检查，逐模型否决项的独立关闭证据；
- 当前文件SHA是否与报告/渲染/编码来源吻合；
- 未通过项的影响和下一步，不把环境问题或旧报告藏在通过总数里。

## 给用户的交付说明

本次修正了什么；工程、白模、对照的当前链接；实际尺寸/帧率/原声检查结果；明确尚未达到或未验证的目标。只有当前文件满足本次全部要求时才写“完成”。
