# 工作流程与任务管理

## 1. 接单与恢复上下文

读取用户视频、参数截图、画风图、已有 `.blend`、当前交付清单、TODO 和最新纠正。任务标题相同不代表同一项目；侧边栏记录只能作为证据读取，转发或启动别的任务仍须有相应授权。

先盘点可复用内容：原片的镜头切点是否与现有工程一致？工程只覆盖哪一段？音轨是否已内嵌？最近通过的模型、相机、动作、样式来自哪个版本？不要仅按文件名中的“最终”选择。

记录每片原视频 SHA-256、解码帧数、尺寸、帧率分数、视频/音频时长、起始时间戳、音频流与声道。读取元数据后做真实解码验证。文件数不能替代内容覆盖范围。

把来源分成：用户硬要求、参考中直接可见事实、制作推断、待确认项。帧率/尺寸/声音/比较画幅会影响全流程，缺失时先查现有截图和记录；仍冲突再问关键问题，其余分析可继续。

## 2. 固定任务合同

使用[任务模板](task-template.md)，至少写清：

- 每个输入对应哪些交付文件，是否包含完整视频及所有切点。
- 白模尺寸、比较视频总尺寸与每格尺寸、上下顺序、帧率及音视频参数。
- 是否采用用户指定的身份色、球形头、眼高贴面条等样式；焦点标记按实际底色自动计算对立色/互补色并验证亮暗对比，不统一默认黄色。
- 原声是否原样保留；有无用户授权的剪辑、重采样、转码或改速。
- “相似度”的具体覆盖范围、硬门槛、测量方法、误差容限及未验证项。

同一项目内源视频规格不足时，登记限制。例如720p输入可用于做原生4K白模，但参考栏放大不能称为原生4K素材。

## 3. 原片分析

先完整观看并听取原声，再逐镜拆解。用联系表定位变化，对结构、动作、遮挡和交接关键区间读连续帧。看图工具只能证明看过图，不能冒称听过声音或正常速度播放过。

建立镜头表和事件表，先锁定原片标注，再测候选。为被遮挡的关节记录区间或 N/A，避免虚构精确点。具体见[参考与机位](reference-and-camera.md)。

## 4. 空间与动作分层搭建

先场景拓扑与通行空间，再相机，再固定尺寸人物的根运动与姿态，最后手部、道具、细节遮挡。不要把所有误差都推给相机；也不要为每帧拟合而给同一角色任意变比例。

保留用户认可的样式基线，使用独立候选目录。每次脚本重建都明确输入基线和补丁顺序；不要在已打补丁的工程上重复执行会累加变换的补丁。

## 5. 预览与迭代

先低分辨率检查关键帧、切点两侧、动作起止点及全片连续性；重要局部再出实际交付尺寸样本。低清检查确定方向，不能替代最终分辨率的接缝、遮挡和标记检查。

每条反馈按“原片事实 → 当前错误 → 修正范围 → 验收证据”登记。例：不是“手错了”，而是“原片男子上臂近竖直、肘在腰侧、前臂前伸；现版虽握住但肘形反了”。

对一轮修订采用明确的结束条件：当前要求满足、失败项已修、相邻帧无回归。发现授权范围外的残差时记录影响；不能为了省事把它填成通过，也不要无边界重做全片。

## 6. 冻结、渲染、编码、验收

保存候选后重新打开，完成当前范围原生检查与视觉审查。若带明确未通过项先输出候选预览，不能标成最终验收通过。

冻结 `.blend`、相关脚本、输入和音频的 SHA，估算磁盘后再批量原生渲染。每次启动渲染确认路径、帧段、相机、尺寸、引擎和配置；断点续渲必须校验旧帧确属同一冻结源。

按[交付与音轨](delivery-and-audio.md)制作，按[质量门槛](quality-gates.md)验收最终文件。审查通过后由单一整合者更新当前入口、清单、说明和未结事项，历史版保留明确身份。

## 多窗口协作与资源约束

- 独立工作可拆为原片标注、空间/相机、造型/动作、编码验收；分别明确只读输入、写入目录、不可改对象、输出证据。
- 不让多窗口同时改同一 `.blend`、生成器、顶层清单或TODO；变更由整合者基于来源SHA合并。
- 主线程在渲染时，侧聊可做文档、分析或独立候选；未获授权不覆盖正在用的文件。严禁把只读评审角色当作另一个隐式制作方。
- 不复制大批旧缓存作“保险”。保留不可替代输入、有效工程和成片，按需保留可再生帧及证据。清理规则见交付文档。
