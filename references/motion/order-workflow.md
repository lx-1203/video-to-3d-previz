# 从动作底稿接到订单制作

本工作流默认延续已验证的方式：GEM动作 → 指定模型原绑定 → 正向检查机位 → 整段原声上下对照。匹配已支持模板特征时使用暖白模型及蓝色标记，其他profile保留原材质显示色。检查副本只换相机/支持的显示配色，不改原动作和模板；用户有明确身份色或机位要求时，以订单要求为准。这个预览样式不能替代正式场景的身份色规范。

| 阶段 | 执行与产物 | 继续条件 |
| --- | --- | --- |
| 明确范围 | 核对原片、镜头切点、目标人物、模板、起点/时长、音轨与交付要求 | 首次选同一镜头内目标连续可见的短段；默认先5秒 |
| 恢复或新建 | 已有任务先 `status`；新任务 `doctor` 后 `init` | 配置、私有模板和映射真实存在；只运行返回的下一步 |
| 动作底稿 | `extract`，或明确选择外部动作后 `attach-motion` | 真实成功并登记来源/SHA；提取失败先修当前原因 |
| 指定模型 | `retarget`，保存后重开技术检查 | 当前工程与动作同版；保留原网格/绑定和明确适配记录 |
| 连续预览 | `preview`，生成检查副本、整段原声对照、联系表及跟踪报告 | 对照中确认目标、动作阶段、左右、头身/肩肘腕、腿脚和失跟踪区间 |
| 复核后继续 | 按实际证据 `review`；通过的范围进入后续场景、接触和机位制作 | 仅生成影片、检测置信度或一个满意姿势不能替代完整动作复核 |

用户认可某个短段时，记录实际文件、片段和认可范围，作为后续预览的样式/动作基线。常规已授权步骤继续执行；不把认可扩大成其他镜头、整单、世界轨迹或所有接触已通过，也不因内部待修记录忽略用户已经认可的呈现方式。

先修确定的问题，再扩大时长。跟踪目标错误、严重补齐、切镜或腿脚长期不可见时，回到原片分段/目标判断；当前工具没有指定人物锁定或多人独立恢复。不能通过删除坏帧、加速、拉伸或换旧动作冒充完成。新的短段保留真实时间区间及完整试验记录。

复用当前有效动作/工程生成预览，不反复下载已有权重或重跑识别。每个镜头分别建任务，按秒对齐；控制器上限60秒不是保证单次任意长镜头都能识别。AI只执行固定命令、读取JSON与下一步；不临场重写骨骼数学、编码器或白模渲染脚本。

需要继续原片场景、相机、道具、握手/取物等人物接触或正式成片时，回到本次已加载的[主工作流程](../workflow.md)，不递归调用同一主技能；下一次新调用仍须先过在线更新门禁。同甲方人物仅在已指定且该私有技能可用时按 `client-model-standard`，其他项目使用自己的获授权资产。不能把动作工具的检查预览当作最终影片。遵守各制作窗口归属，向负责人交当前动作/sidecar、检查工程、原片区间、对照、SHA和未结项；不覆盖他人原场景或统一交稿入口。
