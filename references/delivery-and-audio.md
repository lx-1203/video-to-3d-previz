# 原声、4K与最终交付

## 规格表必须来自当前任务

下面是来源项目的**范例合同**，不替代新任务的用户规格：

| 项目 | 来源项目约定 |
|---|---|
| 每片核心文件 | 可编辑Blender工程、带原声白模MP4、上原片下白模MP4 |
| 白模画幅 | 原生3840×2160，不能把低清渲染放大冒充原生4K |
| 上下对照 | 3840×4320，每格3840×2160；不拉伸、不擅自裁切 |
| 帧率 | 用户表最低24fps；该项目原片30fps，输出保持30fps及全部帧 |
| 视频 | MP4 / H.264，实测视频码率至少18Mbps，建议30Mbps |
| 音频 | AAC立体声，至少44.1kHz，实测至少320kbps；项目用48kHz |
| 音频中间格式 | 16bit或32bit PCM，不使用24bit；项目采用16bit WAV |

来源参数图还要求参考视频4K，但实际给到的是1280×720。应记录输入不足：放大参考栏只满足输出尺寸，不能凭此宣称原片质量达标。更高分辨率原片需要用户提供或明确接受现有输入限制，不伪造源信息。

“上下对照4K”需区分整张画布4K和每格4K。该项目采用后者；新任务尺寸不明确时先解释这一区别，避免擅自把两格压成1920×1080。两份影片应使用同一白模帧序列与同一时间映射。

AAC不是PCM位深格式。不要用播放器显示的 float sample format 来宣称压缩音轨“32bit无损”。分别记录PCM中间文件位深、AAC编码、采样率、声道和实测码率。

## 原声保留链

1. 从对应原片直接提取音轨，保存不重编码的原压缩音频副本；无法流复制的容器情况明确说明。
2. 按统一解码参数创建时间轴WAV，保留原起点、尾部及全部内容，不擅自去噪、归一化、配音、加噪、改速或叠加原片与白模的两条声音。
3. 将WAV内嵌Blender，另提供正确相对路径的外部资产副本。另存后重开检查 packed 数据、路径、VSE起点、音量及是否静音。
4. 对最终两种视频只编码一次音轨，两次封装复制同一份AAC；比较AAC包序列可证明两片共用声音。
5. 与原片按同参数解码的PCM比较声道、样本、波形相关性、采样级延迟及尾段；与原压缩音轨比较时区分流复制与有损转码。

重新编码后的AAC不能宣称与原AAC字节一致。内容/时序一致、两份输出AAC一致、原AAC归档一致是三个不同结论。相关系数很高也不单独证明无丢尾、无错声道或听觉完全相同；应结合采样与实际试听。

封装前检查视频和音频分别的起止时间。不要无条件使用 `-shortest` 或以视频时长截掉真实原声音尾；也不要为凑容器时长加静音或改变内容。按原片的音画尾部关系处理并记录。

## 码率不能只看命令

来源项目中，默认AAC即使请求512kbps，部分实际素材也只有约264kbps，未达到320kbps。曾使用本机FFmpeg的 `-aac_coder fast -aac_ms 0 -aac_is 0 -aac_pns 0 -b:a 384k`，实测约384kbps。这是当时版本与素材的可行配置，不保证所有编码器都支持或所有素材都达标。

先检查当前编码器帮助及短段真实素材的结果，再整片编码。不能通过加噪、叠音、改声道内容或伪造标签提高音频码率。若支持的配置仍无法兼顾原声与目标参数，准确报告约束冲突。

视频可按要求选择真实CBR配置；来源项目用H.264 high、level6.0、yuv420p、30Mbps和HRD/filler。尺寸/帧率不同需重新核对级别与播放器支持，不照抄level；填充数据可满足传输码率但不提升细节质量。

实测按各流编码包总字节×8/该流时长计算，并记录时长定义、编码包与元数据值；不能用总文件大小除视频时长代替独立视频/音频码率。验证可用FFprobe或PyAV等本机工具，记录实际工具版本。

## 渲染来源与磁盘

原生渲染先出带连续帧号的序列，清单记录实际尺寸、帧段、相机、引擎/设置、输入SHA和每帧SHA。同一目录不混入旧候选。缺帧、重复帧、坏帧都阻止编码。

估算剩余磁盘：用几帧实际PNG均值×剩余帧数，加两份编码暂存、审核图和必要余量；估算随渲染更新。无损PNG压缩可降低空间，不能用降低分辨率替代。

只在已核对有效工程、成片、资产和重建条件后清理可再生缓存。Windows使用同一PowerShell上下文：解析绝对路径，确认位于批准的缓存目录内，仅删除明确模式的帧文件，保存清理清单。不得把源视频、原工程、音频、唯一审查证据或整个production目录当缓存删除；不因磁盘紧张清理其他任务。

## 成片验证与当前入口

- 完整解码最终MP4的视频和音频，检查尺寸、fps分数、准确帧数、逐帧时间戳、总时长、编码、像素格式、声道及实测码率。
- 在每镜、每个关键事件、切点两侧，从最终MP4按既定时间抽帧，与冻结渲染序列对比；上下片分别核对上栏原片、下栏白模。
- 加查本次修改区域，防止大面积未变化背景掩盖蓝色角色仍是旧动作。PSNR等可用于检查“成片来自哪版渲染”，不能当真人对白模的创作相似度。
- 可行时正常速度播放并听取音轨，确认运动连贯、无突闪和声音同步。工具启动失败就记未验证，联系表与全解码不是已完成实时回看。
- 只有全部当前发布条件成立、报告SHA相符，才更新总清单和当前版本入口；中间候选、旧版和已被用户否决的版本保留清楚标识。
- 如果视觉范围仍有残差但允许交付修订，标签写“修订文件/已接受增量/未通过整体目标”，不把技术发布等同全部验收通过。

只有明确的非视觉修复（如内嵌声音外部相对路径）才考虑复用旧帧：保留原渲染源SHA，对受影响整段的求值几何、变换、显隐、相机、灯光、材质、渲染设置及相关依赖验证画面不变，另取实际渲染样本验证，并记录父子版本桥接。证明不足就重渲，不能篡改旧清单SHA来“对上”。
