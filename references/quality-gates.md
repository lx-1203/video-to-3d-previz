# 产品质量与可追溯验收

## 四类结果分开登记

| 验收层 | 要证明的事实 | 不能替代 |
|---|---|---|
| 原生工程 | 可打开、可编辑、资源完整、几何/动画/机位/音轨结构正确 | 实际画面好看或匹配原片 |
| 媒体技术 | 原生渲染来源、尺寸、帧数、编码、码率、解码与原声同步 | 空间、动作和风格相似度 |
| 视觉与动作 | 参考事实、连续运动、遮挡、比例、接触、当前修订要求 | 最终MP4已使用本次工程 |
| 版本与交付 | 以上证据属于同一冻结源，文件和当前入口一致 | 未覆盖需求已经完成 |

每个结果有范围、方法、实际执行记录、输入SHA、证据和结论。状态采用 passed / failed / unverified / not_applicable；N/A只用于确实不适用且有理由的项目，不能包藏必需项。未运行检查不计入通过率。

异常采样必须进入相应必需项的失败判定，不能只写在`intrusion_samples`之类旁路计数里而让`checks_failed=0`。对实际使用的汇总和发布路径注入一份明确越过既定容差的反例，确认具体项目与最终状态都失败；只测试采样器会记录异常还不够。零异常只能支持实际覆盖的对象、表面和帧，不代表全场景零穿插。

## 硬门槛

按当前原片和需求选定并冻结，不机械套用“影院”拓扑：

- 主要空间连接、楼层和遮挡顺序一致，人物处于可承托的地面。
- 角色身份与约定画风一致；胸背、解剖左右、动作发起者不颠倒。
- 已要求还色时，墙地/座椅/木饰面/家具等环境主色和明暗关系在实际渲染与成片中恢复；材质输入、渲染颜色覆盖和输出画面分开核验，不能以角色彩色替代场景还色。
- 球面眼条的侧边贴合，头身无可见空气缝；明确无颈样式没有擅加的外露颈柱；手型、腕掌连续性及至掌端的长度符合认可参考。本条随项目风格适用，不能把所有角色都强制做成无颈块手。
- 逐镜关键背景、门洞朝向/高度、相机俯仰、应露/应遮物、人物比例与相互间距匹配，不能只对齐主体头部。
- 焦点标记由实际承载底色计算对立色/互补色并核验亮暗可辨性，不能继续统一黄色；采用来源色板时第四角色全镜黄色。同角色同材质跨镜的标记映射稳定，换底色会重新计算，无逐帧跳色。材质数值检查与实际渲染检查分别记录。
- 必需动作过程、物件出现时点、接触顺序和持有关系正确。
- 行走、转身、离画、挥手、张臂及贴面互动等受影响事件已对照连续过程；必需的手持物在实际画面中存在，不能用终态截图或接触点为零替代动作验收。
- 无影响当前要求的明显穿插、断肢、浮头、跳位或单帧消失；未解决的物理异常单列量值与可见影响。
- 全片范围、镜头切点、时间映射和原声满足合同。
- 最终文件对应当前验收源，未采用旧版、错帧或被否决成果替代。

硬门槛失败时，其他高分不能抵消。修订局部通过不能自动关闭全片的未结目标。同批模型按模型ID、角色对象、镜头与否决项逐条关账：一项多模型时每个实例都要验证，一个模型多项错误时分别出证据。编号到工程映射缺失记未验证，不能按附件顺序猜配，也不能声称已修好未打开的用户工程。

## 如何处理“95%以上”

先给出可复算的验收定义，再对照候选。结构与运动应有独立维度、逐角色/逐镜结果及最差关键帧；报告标注误差与未观察范围。实拍和白模材质差异很大，不把SSIM/像素PSNR直接解释成用户的整体观感相似度。

可以采用空间点/线/区域、人物位置与比例、事件时点/接触等指标，但阈值、权重和误差预算要在看候选结果前固定。若需要百分制，用名称说明它是“约定的空间与构图匹配分”，不是普遍意义上的真实相似率。

来源案例的旧协议是一个**方法示例，不是默认行业标准**：

- 参考1280×720，对角线D；点误差e按D归一化，P=100×mean(max(0,1-e/0.20))。
- 可见对应线夹角θ，L=100×mean(max(0,1-θ/40))；区域R=100×mean(IoU)。
- 建筑A=0.45P+0.25L+0.30R；人物B分别由位置与尺寸得分计算，不能跨角色平均掩盖个体问题。
- 事件时点以帧差计分，但接触、顺序、可见性仍是硬门槛；没有原片事件基准时记未量化。
- 原协议对建筑、每个角色、动作和总分均设门槛，并保留人工标注误差区间。任一必需项未知，整体95%仍未证实。

新项目可用更适合的分法；不要搬用影院的80/15/5权重让其他题材的动作只占5%。即使保留旧协议，也须保存原始标注、公式、版本与全部失败样本，不能为了过线修改归一化分母、删除不利帧或把未知填100。

区间跨越阈值时写“边界不确定”，继续精标或保留未通过；名义值高于95不等于保守下界通过。已用于调机位的holdout要改标为训练/调参样本；需要泛化证明时另选未用帧。

## 反馈闭环与覆盖账本

在本轮候选调参前，把用户圈出的错误定位回原片完整画幅：登记截图对应的原片零基帧/PTS、Blender帧、镜头、角色与置信区间。再固定需要观察什么、检查哪些连续帧和哪些对象。截图红框是问题区域，不直接当作人体边界。继承旧版人物/相机只证明未改，不能证明其动作、朝向和构图符合本轮参考。

| 否决项 | 必须分别观察的事实 | 不能作为替代证据 |
|---|---|---|
| 躯干朝向错误 | 肩线、胸/背可见面、骨盆与支撑方向；头部方向另列；转身全段及离开镜头 | 头条朝向、胸标存在、仅根旋转数值 |
| 主角或配角没对齐原片 | 每个角色各自的头/肩/躯干屏幕位置、画面占比、画内裁边、前后层级；用相同帧与完整画幅 | 只对齐主角头部，或全员平均误差 |
| 前臂没有覆盖掌部 | 按当前认可模板/用户解释核对肘到掌端的实际外轮廓、袖口/掌部覆盖和总长，保留认可掌长 | 缩小手掌、仅有8顶点平掌、腕点距离或骨长恒定 |
| 肘/手/杯穿插 | 每个受影响角色的上臂、前臂、掌面与躯干/另一肢体/台面/道具；从接近到分离；分类正常关节衔接与可见穿透 | 仅红角色若干顶点对躯干的检查，或一张不穿的关键帧 |
| 托盘/杯子突现 | 从出现前到首次可见、逐渐显露、放置及退手的连续段；杯与托盘各有来源、持有/支撑和遮挡 | 道具已建出、终态可见、显隐曲线有关键帧 |

对每项分别登记原生检查、同帧实际渲染和最终成片复核；某项不需某层证据时说明理由。预先选定的连续区间不能在汇总时缩成首尾两帧，也不能用其他角色或其他帧的通过结果补空白。至少将本次用户否决的旧版作为同一判据的反例：若它仍全通过，先修判据及覆盖范围，不直接认定新版修好。原片看不清的部分保留区间/未验证，不为了产生一个精确数值而编造。

检查名称与结论范围相同：只测腿长就只说腿长，坐标记录不等于同帧动作已比较，空集合的`all()`不证明未覆盖项目通过。方向、阶段、形态、接触与穿插分别关账；被否决旧源可在授权清理前保留精简失败图、SHA与关键测量，不必为反例长期保留整套大缓存。

较多对象/反馈并行时，可将冻结协议与审查结果保存为JSON，使用 `scripts/validate_review_coverage.py` 防漏账。协议只列本轮适用的必需检查；`checks`的ID应带镜头、角色、反馈和证据层，帧号均为**原片零基序号**，连续区间展开为完整序列。示例字段如下（SHA填写实际值）：

```json
{"source_video_sha256":"<原片SHA>","checks":{"shot2_server_arm_visual":{"source_frames":[209,210,211]}}}
```

审查结果关联协议字节SHA、当前选中工程SHA和原片SHA；每项填写实际执行状态、实际查看帧与证据文件SHA。证据相对路径以结果JSON所在目录为基准：

```json
{"protocol_sha256":"<协议SHA>","candidate_sha256":"<工程SHA>","source_video_sha256":"<原片SHA>","checks":{"shot2_server_arm_visual":{"executed":true,"status":"passed","source_frames":[209,210,211],"evidence":[{"path":"arm_review.json","sha256":"<证据SHA>"}]}}}
```

```text
python <技能目录>/scripts/validate_review_coverage.py --protocol protocol.json --report review.json --candidate selected.blend --source-video source.mp4
```

遗漏检查、未执行、failed/unverified/N/A、必需帧未覆盖或输入/证据SHA变化均返回非零。它只核对账本完整性与文件绑定，**不读取网格/图像内容，也不能证明申报的观察属实、协议覆盖充分或视觉通过**。逐项证据仍由实际执行者与复核者审查；证据内部仍有未解决失败，或协议只列技术项时，即使返回`coverage_complete`也不能关闭视觉反馈。部分交稿保留未通过状态，此工具不用于把部分交稿改成完整验收通过。

## 独立复核

有权限且有资源时，给复核者原片、需求、冻结输入和候选实际产物，让其独立形成对应事实。不要只给制作方结论、expected函数或“这里已经修好了”的暗示。

复核者读取最终保存文件的求值结果，必要时单独提取关节/网格和相机投影；制作方依据报告修复。相同解算函数重复运行只能证明一致性，不能证明符合原片。

区分未修改区域的回归检查与本次目标的正向验收。旧动作数据未变、相机未变、骨长稳定是回归证据；被本次反馈否决的旧数据必须重新对原片判断，不能把`unchanged`列为它的通过条件。局部距离、包围盒或接触测试之外，检查实际可见轮廓与头/胸/骨盆/四肢朝向；胸骨端在头球内、头身最短距离很小都不能证明头型、头向正确或没有深埋。

读取制作方的原生审计报告、核对其SHA，与独立重新打开工程并重算是两种覆盖范围，须分别写明。最小表面距离接近零不证明自然连接或没有深埋；代理盒的角点拟合不证明实际头、胸、骨盆和四肢的可见轮廓正确。屏边的抗锯齿像素保留实测数量及分辨率，不为汇总“零问题”抹掉，也不把没有可见影响的数值残差机械升级为整片返工。

有效反例控制：用同一检验去测用户否决的旧版，确认能检出那个具体缺陷。案例中旧版握手距离几乎为0、骨长稳定，却被肩肘腕形态测试检出158个失败样本。若新测试连旧错版也全部通过，检查定义和覆盖范围。

## 连续性与覆盖

静态构图检查、事件周围逐帧检查、全镜连续性与正常速度播放各有用途。全片联系表覆盖了474帧，并不代表每帧细节都以全尺寸看过；报告缩略图尺寸和重点大图范围。

局部补丁还要覆盖与旧动作衔接处的相邻连续帧，复核实际掌端、足端、头部轮廓及世界/屏幕位移，并对照原片真正的阶段转换；不能只查补丁内或首尾关键帧。旧端点保持不变不证明该端点正确，也不证明过渡连续。若接触阶段依赖算法覆盖终点而未读后续原片，阶段验收仍未验证；固定模板在真实有限接触面上已不可达时，先按[手臂与伏身](character-and-motion.md#手臂与伏身)校正约束，不继续凭局部接触数值关闭反馈。

模型审查不能替代实际渲染；渲染审查不能替代最终MP4；自动相邻帧差分不能证明无穿插；单张截图不能证明动作时序。最终复核重点重读用户最近否决项，防止检查多但漏掉真正问题。

播放器以1倍速到达ended只证明播放运行到了末尾。除非实际连续观察画面或听取声音，否则不能把该状态写成完整视觉回看或试听通过。报告分别列出人工所看关键帧、连续观察范围、解码核验和播放器运行状态。

## 最终报告与发布判断

使用[记录模板](task-template.md)逐项关联要求、证据、SHA、状态和剩余偏差。检查结果的布尔值必须真实且严格；缺失报告、旧SHA、未执行、失败、草稿不能被当作发布通过。

区分“某视觉增量可发布”“全部技术输出合格”“全片95%达标”。只有当前合同中的全部必需项得到证据支持，才能宣称完整目标完成。否则提供有效修订成果并列明未结项，不用总检查数量掩盖。

用户明确先交稿时，按[赶稿冻结与导出](delivery-and-audio.md#赶稿时冻结与导出)允许交付标明未结项的选定版本；交稿授权不等于视觉验收通过，也不要求为“完成全部修复”继续违背用户的停止指令。

按环境要求做global-self-review分级：局部检查Light，模块Module，完成声明前Full；代码审查/原生验证/视觉审查范围分别说明。OCR失败或缺失时记OCR未运行并进行有范围的人工检查，不能将人工检查称作OCR通过。
